# Contributing to LuxyOS

Thank you for wanting to help. LuxyOS is in the **design phase**: there is no source code yet. The most valuable help right now is research, small prototypes and review.

## Ways to help now

1. **Pick a task** from [docs/good-first-tasks.md](docs/good-first-tasks.md). Open an issue with the *Research task* template first, so work is not duplicated.
2. **Share an idea** with the *Idea* issue template. Explain the problem it solves for users.
3. **Review the designs** in [docs/design/](docs/design/) with the *Design feedback* template.
4. **Propose an architecture decision** by adding a record to [docs/decisions/](docs/decisions/) in a pull request.
5. **Help with languages**: terminology and review for one of the launch languages ([docs/languages.md](docs/languages.md)).

## Ground rules

- **English** for issues, pull requests, code and documentation.
- **Respect the principles** in [docs/vision.md](docs/vision.md): only what is needed runs, nothing leaves without permission, honest about what works.
- **No telemetry, trackers or ads** in any proposal or prototype.
- **No copied proprietary designs, code or assets** (for example Microsoft's look and icons). Own designs only.
- Keep pull requests small and focused. Describe what changed and why.
- By contributing you agree that your contribution may be published under the project licence once it is chosen (see [LICENSE.md](LICENSE.md)).

## Pull requests

- One topic per pull request.
- Link the related issue.
- For documentation: plain language, short sentences, tables for comparisons.
- Sign off your commits (`git commit -s`) to certify you have the right to submit the work (Developer Certificate of Origin).

## Prototypes

Prototypes live in their own branch or fork until the code structure is decided ([docs/roadmap.md](docs/roadmap.md)). Include how to build and run it, and what you measured.

## Behaviour

Everyone is welcome. See the [Code of Conduct](CODE_OF_CONDUCT.md).
